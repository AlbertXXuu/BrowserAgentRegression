This reading companion summarizes the preserved [calibration JSON](v1.0.0-calibration.json) and

## Protocol and scope

- Protocol: `browser-agent-regression-controlled-ui-v1`; schema `1.0`; recorded tool version `1.0.0`.
- Evidence kind: `synthetic-calibration`, using the deterministic `reference` and `popup-blind`
  drivers. Each task/driver/variant cell is repeated 3 times.
- Tasks: `checkout.basic.v1`, `catalog.find-and-save.v1`, and `preferences.notifications.v1`.
- Calibration: 2 drivers × 3 tasks × 2 variants (`clean`, `popup-overlay`) × 3 repetitions =
  36 attempts.
- Reference oracle: 1 driver × 3 tasks × 4 variants (`clean`, `popup-overlay`, `delayed-render`,
  `layout-shift`) × 3 repetitions = 36 attempts.
- Recorded calibration environment: Python `3.11.0`, Playwright `1.62.0`, browser `151.0.7922.34`,
  platform `Windows-10-10.0.26200-SP0`. Calibration creation time: `2026-08-23T20:50:17.306226+00:00`.

Independent ordered fixture checkpoints determine success. The JSON retains fixture SHA-256
hashes, per-attempt outcomes and durations, bounded error messages, summaries, and regressions.

## Calibration results

Each result below is successful attempts / measured attempts. The first failed checkpoint refers
to the popup-blind candidate on `popup-overlay`.

| Task | Reference, clean | Candidate, clean | Reference, popup | Candidate, popup | First failed checkpoint | Localization agreement |
|---|---:|---:|---:|---:|---|---:|
| `checkout.basic.v1` | 3/3 | 3/3 | 3/3 | 0/3 | `checkout.email.accepted` | 100% |
| `catalog.find-and-save.v1` | 3/3 | 3/3 | 3/3 | 0/3 | `catalog.query.applied` | 100% |
| `preferences.notifications.v1` | 3/3 | 3/3 | 3/3 | 0/3 | `preferences.product_updates.disabled` | 100% |

Both drivers pass every clean-page attempt. On popup pages, the candidate-minus-reference success
rate delta is −100 percentage points for each task (`delta = -1.0` in JSON), producing 3 localized
regressions. All 9 failed attempts agree with their task's first failed checkpoint. In total the
calibration records 27/36 passing attempts and 9/36 failures; the intended failures confirm that
the harness detects this deliberately injected popup-handling regression.

The separate reference-oracle report passes 36/36 attempts across all 4 variants. The v1 comparison
does not test the popup-blind candidate on `delayed-render` or `layout-shift`.

## Separate real-agent feasibility evidence

The historical [Phase 0 Gate C 02 record](phase0-deepseek-gate-c-02.md) and its
[raw JSON](phase0-deepseek-gate-c-02.json) preserve a Browser Use + DeepSeek run at source revision
`b817b68`, dated 2026-08-15. It passed 3/3 clean-page tasks and 9/9 independent checkpoints, with
one attempt per task. All three trajectories contained recoverable empty or malformed model
outputs; checkout reached the required DOM state even though the agent reported failure.

That run supports integration feasibility only. Repeated model reliability and real-agent
robustness to the UI variants were not established by it. The [evidence index](README.md) also
retains preceding failed runs and their diagnoses. These real-agent records are separate from
the deterministic v1 calibration above.

## Verification and interpretation

After installing the project, verify the preserved evidence from the repository root:

```powershell
browser-agent-regression verify --report docs/evidence/v1.0.0-calibration.json
browser-agent-regression verify --report docs/evidence/v1.0.0-oracle.json
```

Verification recomputes summaries and regressions from attempts, checks checkpoint contracts and
fixture hashes, and rejects credential-shaped fields. Deterministic-driver outcomes, summaries,
and localization should reproduce; timestamps, durations, and environment versions can vary.

These results establish controlled harness calibration for the recorded tasks, fixtures, and
drivers. They do not rank models or agent frameworks. First-failure localization identifies the
first unmet outcome checkpoint; causal explanations require additional evidence, as described
in the [failure taxonomy](../research/failure-taxonomy.md).
