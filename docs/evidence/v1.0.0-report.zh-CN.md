# Browser Agent Regression v1 校准报告

[English](v1.0.0-report.md) · 简体中文

本文依据仓库版本 `48fc157d4471148551c3be3843b0fed64933a2cf` 中保存的
[校准 JSON](v1.0.0-calibration.json) 和 [oracle JSON](v1.0.0-oracle.json) 编写，
与[英文报告](v1.0.0-report.md)对应。原始 JSON 与[证据协议](../evidence-schema.md)

## 协议与范围

- 协议：`browser-agent-regression-controlled-ui-v1`；结构版本 `1.0`；记录的工具版本 `1.0.0`。
- 证据类型：`synthetic-calibration`，使用确定性的 `reference` 与 `popup-blind`
  驱动。每个任务/驱动/变体组合重复 3 次。
- 任务：`checkout.basic.v1`、`catalog.find-and-save.v1` 和 `preferences.notifications.v1`。
- 校准：2 个驱动 × 3 个任务 × 2 个变体（`clean`、`popup-overlay`）× 3 次重复 = 36 次尝试。
- 参考 oracle：1 个驱动 × 3 个任务 × 4 个变体（`clean`、`popup-overlay`、`delayed-render`、
  `layout-shift`）× 3 次重复 = 36 次尝试。
- 记录的校准环境：Python `3.11.0`、Playwright `1.62.0`、浏览器 `151.0.7922.34`、
  平台 `Windows-10-10.0.26200-SP0`。校准创建时间：`2026-08-23T20:50:17.306226+00:00`。

成功与否由测试页面中独立、有序的检查点决定。JSON 保存了测试页面与任务清单的 SHA-256、
逐次结果与耗时、长度受限的错误信息、汇总和回归记录。

## 校准结果

下表数值均为成功次数 / 实测次数。“首个失败检查点”指 `popup-blind` 候选驱动在
`popup-overlay` 变体下的首个失败点。

| 任务 | 参考驱动，无弹窗 | 候选驱动，无弹窗 | 参考驱动，有弹窗 | 候选驱动，有弹窗 | 首个失败检查点 | 定位一致率 |
|---|---:|---:|---:|---:|---|---:|
| `checkout.basic.v1` | 3/3 | 3/3 | 3/3 | 0/3 | `checkout.email.accepted` | 100% |
| `catalog.find-and-save.v1` | 3/3 | 3/3 | 3/3 | 0/3 | `catalog.query.applied` | 100% |
| `preferences.notifications.v1` | 3/3 | 3/3 | 3/3 | 0/3 | `preferences.product_updates.disabled` | 100% |

两个驱动在无弹窗页面上的所有尝试都通过。在有弹窗页面上，每个任务的“候选减参考”成功率
差值均为 −100 个百分点（JSON 中 `delta = -1.0`），因此得到 3 个可定位的回归。
全部 9 次失败都一致定位到各自任务的首个失败检查点。校准共记录 27/36 次通过、9/36 次失败；
这些预设失败说明测试框架能够发现人为注入的弹窗处理回归。

独立的参考 oracle 报告覆盖全部 4 个变体，36/36 次尝试通过。v1 对照实验没有在
`delayed-render` 或 `layout-shift` 上测试 `popup-blind` 候选驱动。

## 独立的真实 Agent 可行性证据

历史 [Phase 0 Gate C 02 记录](phase0-deepseek-gate-c-02.md)及其
[原始 JSON](phase0-deepseek-gate-c-02.json) 保存了 2026-08-15 在来源版本 `b817b68` 上完成的
Browser Use + DeepSeek 运行。每个任务尝试一次，3/3 个无弹窗任务和 9/9 个独立检查点通过。
三个轨迹都出现过可恢复的空输出或格式错误输出；结账任务虽然被 Agent 自报为失败，
独立评分器仍确认其达到了所需 DOM 状态。

该运行只支持集成可行性，尚未证明模型多次运行的可靠性，也未证明真实 Agent 对这些 UI
变体的鲁棒性。[证据索引](README.md)同时保留了此前失败的运行与诊断记录。
这些真实 Agent 记录与上面的确定性 v1 校准分开解释。

## 验证与解释

安装项目后，在仓库根目录验证保存的证据：

```powershell
browser-agent-regression verify --report docs/evidence/v1.0.0-calibration.json
browser-agent-regression verify --report docs/evidence/v1.0.0-oracle.json
```

验证器会从逐次结果重新计算汇总与回归，检查检查点合同和测试页面哈希，并拒绝凭据形态字段。
确定性驱动的结果、汇总和定位应当可复现；时间戳、耗时和环境版本可以变化。

这些结果证明了所记录任务、测试页面和驱动上的受控框架校准效果，不能用于模型或 Agent
框架排名。首个失败点定位只标识第一个未满足的结果检查点；因果解释需要额外证据，
详见[失败分类](../research/failure-taxonomy.md)。
